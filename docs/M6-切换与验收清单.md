# M6 切换与验收清单（v2）

> 用途：在真实设备上把正在运行的旧插件（`plugin/`）切换为 v2（`plugin-v2/`），并逐项验收。
> 原则：**不预装**；切换前保留旧版与 profile 备份；任何一步失败都能回滚。
> 关联文档：[系统架构说明](架构说明-v2.md) ｜ [安装说明](安装说明.md) ｜ [重构策划案](重构策划案-v2.md)

## 0. 前置确认

- [ ] 公开工具仓库已更新到最新（`git -C <工具仓库> pull --ff-only`）；
- [ ] 旧版仍在 `plugin/`（未删除）；
- [ ] `legacy/plugin-v1/` 已生成归档副本（M6 自动完成）；
- [ ] 私有数据仓库地址已准备好（如 `git@github.com:<你>/deepseek_cloud.git`）且本机凭据可用；
- [ ] 记录当前 profile 依赖：
  ```powershell
  (Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json" -Raw | ConvertFrom-Json).dependencies.'dsh-plugin-cloud-sync-panel'
  # 期望：link:<工具仓库>/plugin
  ```

## 1. 干净克隆安装（推荐路径）

```powershell
# 1) 新克隆（可替换已有工具仓库位置）
git clone git@github.com:neigjborFrank/dsh-cloud-sync-tools.git C:\Users\<你>\Documents\deepseek-harness\cloud-sync-tools-v2

# 2) 安装（默认安装 plugin-v2，不登记任何仓库）
C:\Users\<你>\Documents\deepseek-harness\cloud-sync-tools-v2\install\一键安装.cmd
```

安装脚本会：备份 profile `package.json` → 写入 `link:...\plugin-v2` → 把插件加入 `dsh.profile.bundles` → 尝试 `pnpm install` → 配置仓库基础项；**不会**写 `repos.json`。

## 2. 重启并确认加载

1. 彻底退出 DSH（含托盘）后重新启动；
2. 侧边栏底部出现「同步」按钮；
3. 点击后菜单为 v2 四项：**上传会话… / 下载会话… / 云端与同步… / 仓库管理…**。

> 若按钮不出现：确认 profile 依赖已是 plugin-v2、pnpm install 成功；查看 DSH 日志中的插件加载错误。

## 3. 配置私有仓库（保存会话的目标仓库）

1. 「同步 → 仓库管理…」；
2. 在"私有仓库地址"填入 `git@github.com:<你>/deepseek_cloud.git`（或本机已有仓库绝对路径）；
3. 点「添加仓库」：
   - URL 模式：自动克隆到 `%USERPROFILE%\.dsh\cloud-sync\repos\<名称>\`；
   - 本机路径模式：直接登记已有仓库；
4. 列表出现该仓库且无"（本地缺失）"。

## 4. 功能验收用例

| # | 操作 | 期望 |
|---|---|---|
| 1 | 上传一个小工作区的会话 | 输出含「目标仓库…」「项目 … 文件 N」；「云端与同步」状态为「一致」 |
| 2 | 查看 GitHub 私有仓库 | `store/<项目>/files/…` 保持原始目录结构；`index/projects/<项目>/…` 有 meta/manifest/sessions |
| 3 | 子目录工作区上传（如工作区的 `sub/`） | 输出「已按父项目视角合并到…」；不新建重复项目 |
| 4 | 上传父目录（包含已有项目） | 输出「已将旧项目…并入当前更大的工作区」；旧项目消失 |
| 5 | 下载到新目录（勾选同时下载工作区） | 文件还原、校验通过、会话 cwd 改写、新工作区出现在侧边栏 |
| 6 | 仓库管理移除仓库 | 列表减少、绑定被清理；至少保留一个仓库 |
| 7 | 重启 DSH | 插件正常加载、按钮存在、数据不丢 |

## 5. 验收命令（开发侧）

```powershell
node --test tests/unit/core.test.mjs tests/unit/session_repo.test.mjs        # 13 项
node tests/integration/api.test.mjs <工具仓库>\plugin-v2 <临时目录> 8910     # 23 项
node tests/integration/compat.test.mjs <私有仓库克隆> <临时目录>              # 真实数据只读兼容
```

## 6. 回滚到旧版

```powershell
# 1) 修改 profile 依赖回 plugin/（或恢复安装时生成的 package.json.bak-*）
# 2) 在 profile 目录执行 pnpm install
# 3) 完全退出并重启 DSH
```

旧插件代码保留在 `plugin/`，归档副本在 `legacy/plugin-v1/`；数据仓库布局 v2 兼容读取，回滚不会破坏数据。

## 7. 验收通过后（清理）

- [ ] 保留 `legacy/plugin-v1/`（作为历史归档，可删除但不建议）；
- [ ] 确认不再需要回滚后，可删除 `plugin/` 或将其也移入 `legacy/`；
- [ ] 更新 README「当前状态」为 v2 默认；
- [ ] 在 GitHub 打 tag（如 `v2.0.0`）。
