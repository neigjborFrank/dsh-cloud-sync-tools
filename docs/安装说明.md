# 云端同步面板：安装说明（v3.0.0）

界面完全在 DSH 内：点侧边栏底部的 **⇅ 同步**，在按钮旁弹出悬浮菜单。
宿主内置 HTTP 服务（仅回环 127.0.0.1:8732），无子进程、无 cmd 窗口。

---

## 一、组成

| 部分 | 位置 |
|---|---|
| 客户端（按钮与菜单） | `plugin/client.js` |
| 宿主（HTTP 服务 + 业务） | `plugin/index.js` + `plugin/lib/*` |
| 仓库登记 | `%DSH_HOME%\cloud-sync\repos.json` |
| 云端仓库 | 你自己的私有 Git 仓库（支持登记多个，含 git-lfs） |

生命周期：DSH 启动时插件随宿主加载并监听 8732；DSH 退出时随之关闭。

---

## 二、使用流程

### 上传
1. **上传会话…** → 选项目 → 勾选会话（默认全选，归档会话隐藏）；
2. 工作区**始终全量上传**（不随会话数量重复存储）；
3. 登记了多个仓库时，先选「上传到哪个仓库？」；
4. 超过 95MB 的文件走 **git-lfs**（可在别的机器恢复），清单记录在 `large.json`；
5. 每次上传产生一次 git commit：完整历史、对比与恢复都在 GitHub / git 上（见文末「版本历史与恢复」）。

### 下载
1. **下载会话…** → 选项目 → 勾会话 → **下载**；
2. 弹出**系统文件夹选择框**；没有原生选择框时退回可编辑路径输入；
3. 确认框可勾选「同时下载工作区」（默认勾选）：
   - 勾选：工作区镜像到所选目录，会话 cwd 改写到该目录，并自动登记为新工作区；
   - 不勾选：只恢复会话文件（cwd 保持原样）；
4. 本地多余文件移入 `.csp-trash-<时间戳>/`（不参与上传）。

### 云端与同步
单视图（已合并原「检查变更」），按「工作区 → 会话」层级展示名称与同步状态：

- 工作区：`一致` / `有未上传改动（改 X / 增 Y / 删 Z）` / `云端未上传` / `本地缺失`；
- 会话：`一致` / `内容不同` / `未上传` / `仅云端` / `已归档`；
- 多仓库的项目按名字合并，项目行显示所属仓库名；
- 位于 DSH 安装目录内且未上传的工作区会被忽略（汇总里注明数量）。

## 三、仓库登记与多设备

### 安全约定（重要）

- **工具所在仓库 ≠ 同步仓库**。插件启动时**不会**自动把当前仓库登记为同步仓库；
- 同一私密仓库地址才能互相同步；地址不同 = 两个互不相通的云端；
- 把自己的工具版本发给别人时，别人默认看不到、也连不上你的私有仓库，必须在自己的「仓库管理…」里显式登记他们自己的仓库。

### 登记仓库

菜单 **仓库管理…**：

- 填**私有仓库地址**（如 `git@github.com:you/repo.git`）→ 自动克隆到 `%DSH_HOME%\cloud-sync\repos\` 并登记；
- 或填**本机已有仓库的绝对路径**（该目录必须已 `git clone`）→ 直接登记，不再复制；
- 可登记多个；移除只取消登记，不删除本地克隆。

**工作区 → 仓库绑定**：上传成功后会记住「这个工作区默认传到哪个仓库」；之后再上传同一工作区时，仓库选择框会自动预选绑定的仓库（仍可手动改）。
这只是「记住上次的选择」，**不强制一一对应**：仓库如何划分完全由使用者自行整理——可以多个工作区共用一个仓库，也可以一个工作区一个仓库；插件不会自动创建仓库，也不需要 GitHub Token。

### 新设备安装

1. **准备**：安装 DSH 桌面版并启动一次；安装 Git 并配置仓库访问方式（SSH key 或 HTTPS 凭据）；建议装 git-lfs。
2. **获取工具**（二选一）：
   - `git clone <工具仓库> D:\dsh-cloud`（放在安装目录之外）；
   - 或下载 `_repo/install/一键安装.cmd` 单独运行，按提示输入地址，自动克隆。
3. **一键安装**：双击 `_repo\install\一键安装.cmd`
   （检查环境 → 插件 link 进 DSH profile → pnpm 安装依赖 → 配置 longpaths/提交身份/main 分支）。
   - 默认**不登记**任何同步仓库；确实要登记本次克隆，可运行 `一键安装.cmd -RegisterRepo`。
4. **重启 DSH**（托盘完全退出再启动），侧边栏出现「同步」。
5. **登记自己的私有仓库**：同步 → 仓库管理… → 填地址或本机路径。
6. **验证**：云端与同步视图应展示该仓库中的项目与会话。

### 其它说明

- 插件从自身安装位置推导仓库根目录，因此不同设备/不同克隆路径都可直接工作；
- 多仓库逻辑上视为一个云端：视图合并、上传时手动选目标仓库；
- 回滚插件：`_repo/tools/panel/plugin/回滚.cmd`。

## 四、工作区存放位置

**不要把工作区放在 DSH 安装目录（如 `D:\deepseek`）里**——更新器可能清理该目录。

- 下载时由你在系统选择框里决定位置，插件不再保存全局"工作区根目录"配置；
- 推荐放在 `<Documents>\deepseek-harness\` 下；
- 若选择的路径位于安装目录内，下载结果会给出警告。

---

## 五、workspace 注册表安全

DSH 启动时校验 `%DSH_HOME%\storages\workspace.json`，以下任一情况会让 workspace 服务整体不可用（报 `gateway/service-unavailable`）：

- 同一 `sessionId` 被两个 workspace 登记；
- 同一 `path` 被两个 workspace 使用；
- `global.workspaceIds` 与 `tables.workspaces` 不一致。

插件保证：

1. 优先调用 DSH 官方 `ctx.workspaceRegistry.create(path,title)`（内存状态同步）；
2. 服务不可用时回退文件写入：写前备份、写后自校验、失败回滚、原子写入，登记会话前先从其它 workspace 解绑；
3. 启动时自动自愈历史重复登记；
4. 会话归属由 cwd 决定：下载时改写会话 cwd 到目标目录。

手动接口：`POST /api/registry-repair`、`GET /api/registry-status`。

## 六、云端目录结构

```
<仓库根>/
├── _repo/                       插件与工具代码、安装脚本、日志、测试
└── projects/
    └── <项目名>__<路径键>/
        ├── meta.json            项目信息（cwd、会话列表）
        ├── workspace/           工作区
        │   ├── files/...        可读文件树（GitHub 可浏览下载）
        │   ├── large/...        大文件内容（git-lfs 指针）
        │   ├── manifest.json    路径 → 哈希
        │   ├── large.json       大文件清单
        └── sessions/<会话id>/   会话文件
```

## 七、故障恢复

| 现象 | 处理 |
|---|---|
| 新建/打开工作区报 `workspaceController is unavailable` | 重启 DSH 触发注册表自愈，或调用 `/api/registry-repair` |
| 菜单显示"服务未启动" | 确认 DSH 正常启动；查看宿主日志 |
| 提示"还没有登记同步仓库" | 先到「仓库管理…」登记自己的私有仓库 |
| 改了客户端不生效 | Ctrl+R 重载窗口 |
| 改了宿主代码不生效 | 重启 DSH |
| 下载成功但侧边栏没有项目 | 重启 DSH；或手动添加该目录 |
| 大文件下载后是 LFS 指针 | 在云端仓库执行 `git lfs pull` 后重试下载 |
| 下载提示"会话在其它目录还有副本" | 同一会话存在多个 cwd 副本，可删除多余副本 |

## 包含关系智能合并（上传时自动）

上传工作区时会先把它的文件清单与云端已有项目对比，自动判断包含关系，并按**最大的工作区**合并：

| 情况 | 处理 |
|---|---|
| 当前工作区是某个云端项目的子目录 | 按父项目视角合并：文件落到父项目的对应子路径（如 `files/sub/...`），不新建项目 |
| 当前工作区包含某个云端项目（更大） | 把旧项目整体迁入当前项目（旧文件加子路径前缀、会话一并迁移），删除旧的重复项目 |
| 同一工作区（cwd 相同） | 正常更新该项目 |
| 同路径但内容不同 | **保留云端旧版**，新上传的内容存到 `conflicts/<时间戳>/<路径>` 并在上传结果里列出，不静默覆盖 |
| 无包含关系 | 作为新项目上传 |

合并后项目会记录 `aliases`（被合并进来的子目录及其在项目内的子路径），以后从任一子目录上传都会自动落到同一项目。

## 九、版本历史与恢复（用 GitHub / git）

插件不保存自己的版本备份；每次上传都是一次 git commit，仓库保留每个文件的历史（内容自动去重）。

| 操作 | 方法 |
|---|---|
| 看历史 | GitHub 仓库 → Commits；或 `git log --oneline -- projects/<项目>/workspace` |
| 看某次提交里的文件 | GitHub 打开该 commit 浏览；或 `git show <commit>:projects/<项目>/workspace/files/<文件>` |
| 恢复整个项目到某次提交 | `git checkout <commit> -- projects/<项目>` 后提交并推送 |
| 撤销某个提交 | GitHub 的 Revert（生成反向提交），或本地 `git revert <commit>` |
| 下载某个历史版本 | 在 GitHub 对应 commit 页面下载文件，或 `git archive <commit>` |
