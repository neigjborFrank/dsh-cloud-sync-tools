# DSH 本地数据落盘规则（用于项目与对话归档）

> 结论基于本机实测（`%USERPROFILE%\.dsh`，DSH 0.2.0-rc.2 运行时）与安装包内实现代码（`app.asar` 中 `projectKey` / `sessionDir` / `generationLogPath` 等函数）。
> 目标：确保归档下载回来后**放到正确位置就能被 DSH 识别**。

---

## 一、根目录结构

`DSH_HOME`（本机 `C:\Users\<user>\.dsh`）下：

| 路径 | 内容 | 归档相关性 |
|---|---|---|
| `sessions/` | **对话日志**（按项目目录分组） | ★ 必须 |
| `attachments/` | **附件对象库**（图片等，内容寻址） | ★ 必须（有图片时） |
| `storages/workspace.json` | 项目（工作区）注册表：路径、标题、会话列表、归档/置顶标记 | ☆ 可选 |
| `storages/session_projcache/sessions/<id>.json` | 会话投影缓存（标题、沙箱模式、目标等） | ☆ 可删，会重建 |
| `profiles/<name>/` | 插件与运行配置（package.json、cordis.patch.yml、node_modules） | ✗ 不属于会话归档 |
| `skills/` | 技能包 | ✗ |
| `dsh-runtimes/`、`llm-deepseek/` | 运行时与模型缓存 | ✗ |
| `.credentials.yaml`、`.anonymous-user-id` | 账号凭据 | ✗ **绝不能归档** |

## 二、对话日志：位置与命名

### 2.1 目录公式

```
$DSH_HOME/sessions/<projectKey(cwd)>/<session-id>/session.v<版本>.jsonl.zstd
```

- `cwd` 为会话的工作目录；
- `cwd` 缺失时目录名为 `_no-cwd`；
- 会话目录名 = `session-id`（`session-<uuid>`，本身是安全路径段）；
- 当前版本为 **v4**，文件名 `session.v4.jsonl.zstd`；历史版本为 `session.jsonl.zstd`(v0)、`session.v1.jsonl.zstd` … `session.v3.jsonl.zstd`。

### 2.2 `projectKey(cwd)` 精确算法（从实现中还原）

逐字符处理：

| 字符类别 | 处理 |
|---|---|
| `/`、`\`、`:` | 输出一个 `-`，且**连续的这些字符只输出一个**（`separatorRun` 去重） |
| 字母、数字、`.`、`_`、`-` | 原样保留 |
| `~` | 不保留（作为转义前缀） |
| 其他字符 | 输出 `~` + 该字符码位的 4 位大写十六进制（`~XXXX`） |

最后：去掉开头连续的 `-`，为空则用 `root`，截断到 251 字符，两端各加 `--`。

伪代码：

```js
function projectKey(cwd) {
  let readable = "", separatorRun = false;
  for (const ch of cwd) {
    const code = ch.charCodeAt(0);
    if (ch === "/" || ch === "\\" || ch === ":") {
      if (!separatorRun) readable += "-";
      separatorRun = true;
    } else if (ch !== "~" && /^[A-Za-z0-9._-]$/.test(ch)) {
      readable += ch; separatorRun = false;
    } else {
      readable += "~" + code.toString(16).toUpperCase().padStart(4, "0");
      separatorRun = false;
    }
  }
  return `--${(readable.replace(/^-+/, "") || "root").slice(0, 251)}--`;
}
```

实测对照：

| cwd | 目录名 |
|---|---|
| `C:\Users\<user>\Desktop\v13` | `--C-Users-28726-Desktop-v13--` |
| `D:\deepseek` | `--D-deepseek--` |
| `C:\Users\<user>\Documents\deepseek-harness\default-workspace` | `--C-Users-28726-Documents-deepseek-harness-default-workspace--` |

> ⚠️ 归档跨机器恢复时，**目标机的 `cwd` 必须与归档时一致**，否则目录键对不上。若路径变了，需要同时改目录名和日志首行的 `cwd`（见第四节）。

### 2.3 文件格式

- **追加式 JSONL**，每行一条事件；
- 每个追加块是**独立 zstd 帧**（本机实测：2.4 MB 的会话有 2022 帧、3203 条记录），解码需**逐帧解压**再拼接（`zlib.zstdDecompressSync` 只吃一帧）；
- 首行固定为会话头：

```json
{"type":"session","version":4,"id":"session-8d88101a-…","createdAt":1791252701585,
 "cwd":"C:\\Users\\28726\\Documents\\deepseek-harness\\default-workspace",
 "isSeeded":false,"delegationDepth":0,"agentPreset":"standard"}
```

- 其余记录形如 `{"type":"user/message","seq":12,"time":1791252788230,"data":{…}}`；
- 常见类型：`user/message`、`assistant/message`、`tool/call`、`tool/result`、`step/start`、`step/end`、`turn/start`、`turn/end`、`session/title`、`workspace/changes`、`deliverables/presented`。

## 三、附件对象库

```
$DSH_HOME/attachments/v1/objects/<sha256 前 2 位>/<sha256 全 64 位>
```

- **内容寻址**：文件名即内容哈希，重复内容只存一份；
- 会话日志里以引用形式出现：

```json
{"type":"image","attachment":{
  "attachmentId":"sha256:a75c21cd…b7b04",
  "mediaType":"image/png","bytes":89943,
  "width":910,"height":1287,"name":"page-0001.png"}}
```

- 恢复时只需按 `attachmentId` 把对象放回对应路径；**合并是安全的**（同哈希同名，幂等）。

## 四、项目注册表 `storages/workspace.json`

结构（实测）：

```json
{
  "unit": { "name": "workspace", "version": 2 },
  "global": {
    "initialized": true,
    "defaultWorkspaceId": "…",
    "workspaceIds": ["…", "…"],
    "archivedSessionIds": ["session-…"],
    "pinnedSessionIds": []
  },
  "tables": {
    "workspaces": {
      "<workspaceId>": {
        "path": "D:\\deepseek",
        "title": "deepseek",
        "sessionIds": ["session-…"],
        "createdAt": "2026-10-22T09:43:47.497Z",
        "updatedAt": "2026-10-23T01:07:59.389Z"
      }
    }
  }
}
```

要点：

- 它记录**工作区（项目）**：路径、标题、会话归属与排序、归档/置顶标记；
- 实测本机 `sessions/` 里有 3 个项目目录，而注册表只收录 2 个——说明**会话是按目录扫描发现的**，注册表缺失不影响会话本身被读取；
- 因此归档恢复时：**会话与附件是必需项，注册表是可选修饰**（想把项目固定出现在侧边栏列表时再 upsert）。

## 五、会话投影缓存（可重建）

`storages/session_projcache/sessions/<session-id>.json`：

```json
{ "version": 7,
  "record": {
    "identity": {"formatVersion":4,"createdAt":1791252701585,"cwd":"…","isSeeded":false,"inheritedEventCount":0},
    "rows": { "title": {"ver":1,"seq":3159,"val":"通过 dsh 设备流转文件"}, … }
  } }
```

- `rows` 是投影（标题、沙箱模式、目标等），带 `seq` 版本号；
- 属于**派生数据**：删掉后 DSH 会从日志重建（标题可能退化，取决于是否重新生成）；
- 归档时**不必包含**，除非想保留标题等 UI 状态。

## 六、归档与恢复规则（核心）

### 6.1 归档应包含

```
archive/
├── manifest.json                 # 版本、时间、源 HOME、会话数、附件清单、cwd 列表
├── sessions/<projectKey>/<session-id>/session.v4.jsonl.zstd
└── attachments/v1/objects/<xx>/<sha256>
```

### 6.2 恢复到目标机

| 步骤 | 操作 | 校验点 |
|---|---|---|
| 1 | 确认目标机 `cwd` 与归档一致（不一致见 6.3） | 目录键 = `projectKey(cwd)` |
| 2 | 关闭 DSH | 运行中写入会与追加流冲突 |
| 3 | 复制 `sessions/<key>/<id>/` 到 `$DSH_HOME/sessions/` 同名位置 | 文件名版本号保持原样 |
| 4 | 复制附件对象到 `$DSH_HOME/attachments/v1/objects/`（合并） | `sha256` 与引用一致 |
| 5 | （可选）upsert `workspace.json`，把会话挂到对应项目 | `sessionIds` 含新 id |
| 6 | 删除该会话的 `session_projcache` 条目（可选，强制重建） | 下次打开重新生成 |
| 7 | 启动 DSH，打开对应工作区 | 会话出现在列表并可续聊 |

### 6.3 路径不一致时

需要同时改两处，否则日志会被忽略或归错项目：

1. 目录名：`projectKey(新cwd)`；
2. 日志首行 `cwd` 字段（首帧 JSON 的 `cwd`）。

> 首帧是独立的 zstd 帧，可以解压→改 JSON→单帧重压→与后续帧拼接；也可整文件按帧解压、改首行、再逐帧重压（体积不变，但需要 zstd 压缩能力；Node 24 的 `zlib.zstdCompressSync` 可用）。

## 七、风险与注意

| 风险 | 说明 |
|---|---|
| 运行中覆盖 | DSH 打开会话时持有追加句柄；此时替换文件可能被覆盖或读取到半截 |
| 版本号 | 文件名里的 `v4` 必须与内容版本一致；跨大版本升级时旧文件按旧版本文件名保留 |
| 大小 | 会话日志可到数 MB；附件是内容寻址，跨会话重复引用不重复占空间 |
| 凭据 | `.credentials.yaml` 属账号敏感信息，**禁止**进入归档 |
| 时间戳 | 日志内 `time`/`createdAt` 是**毫秒**时间戳 |

## 八、校验工具

`_repo/tools/archive/verify_session.mjs`：

```
node verify_session.mjs <归档根目录或单个会话目录>
```

检查项：

1. 目录名是否为 `projectKey(cwd)` 的正确结果；
2. 文件名版本是否与首行 `version` 一致；
3. 首行是否为 `type:"session"` 且 `id` 与目录名一致；
4. 逐帧解压是否全部成功、记录条数是否连续（`seq` 无大跳）；
5. 日志引用的 `attachmentId` 是否都能在对象库中找到。

输出为可读报告 + 退出码（0 通过，1 有问题）。
