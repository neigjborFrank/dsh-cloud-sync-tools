> 文档目的：让后续维护者（包括 AI Agent）在不读全部代码的情况下，快速理解 v2 的整体架构、模块边界、数据契约与关键流程。
> 维护规则：**每个里程碑结束时同步更新本文件**（尤其"当前状态"与"模块清单"）。
> 相关文档：`docs/重构策划案-v2.md`（需求与分期）、`plugin-v2/README.md`（进度与模块简表）。

- 文档版本：v2.1（对应 M4 完成 / M5 脚本就绪时点）
- 代码位置：`plugin-v2/`（旧插件 `plugin/` 仍在运行，M5 才切换）
- 包名：`dsh-plugin-cloud-sync-panel`（保持与 v1 一致，避免 profile 迁移风险）

## 1. 系统上下文

```
┌──────────────┐   悬浮菜单 / HTTP(127.0.0.1)   ┌────────────────────────────────┐
│ DSH Web UI   │ ◄────────────────────────────► │ DSH Host (Electron/Node 主进程) │
│ (client.js)  │                                │ ┌────────────────────────────┐ │
└──────────────┘                                │ │ 云端同步插件 v2（本仓库）    │ │
                                                │ │ host: HTTP 服务 + 业务逻辑  │ │
┌──────────────────────┐  读写 DSH 本机数据      │ └──────────────┬─────────────┘ │
│ DSH_HOME             │ ◄────────────────────► │                │ git / lfs CLI  │
│ sessions/ storages/  │                        └────────────────┼────────────────┘
└──────────────────────┘                                         ▼
                                        ┌──────────────────────────────────────┐
                                        │ 用户自己的私有 Git 仓库（1..N 个）      │
                                        │ store/（内容） + index/（指示区）      │
                                        └──────────────────────────────────────┘
```

外部依赖：
- `git`（必须）：commit/push/pull/clone、历史与恢复；
- `git-lfs`（可选）：>95MB 大文件内容存储；
- DSH 官方能力（可选）：`ctx.workspaceRegistry`（登记工作区）、`ctx.directoryPicker`（原生目录选择框）；
- GitHub 等平台仅作为 Git 远程托管，不调用平台 API（不需要 Token）。

## 2. 代码地图（plugin-v2/）

```
plugin-v2/
├── index.js                  # 入口：解析 repoRoot → startServer → ctx.effect 注册关闭
├── package.json              # 包名/导出；dsh.bundle + dsh.client 声明
├── cordis.patch.yml          # 插入 profile 的层栈（端口 8732）
├── README.md                 # 进度与模块简表
├── lib/
│   ├── shared.js             # 常量/限制/schema 版本、AppError、原子读写、哈希、时间戳
│   ├── core/                 # 纯业务核心（不感知 HTTP / 前端）
│   │   ├── layout.js         # store/index 路径约定、projectKey/projectName、路径关系、v1 只读兼容
│   │   ├── manifest.js       # 工作区扫描→清单（路径/大小/sha256；大文件、超长路径）
│   │   ├── project.js        # 项目元数据、列表/查找、alias、v1 布局回退
│   │   ├── mirror.js         # 内容镜像写入（mirror/union、scope、冲突隔离、LFS 落盘）
│   │   ├── lfs.js            # LFS 指针识别、大文件恢复
│   │   ├── merge.js          # 上传包含关系分析、合并迁移（子目录并入/旧项目并入新父项目）
│   │   ├── download.js       # 下载镜像（校验、回收目录、大文件恢复）
│   │   ├── session.js        # 会话枚举/上传/下载、cwd 改写、workspace-ref
│   │   ├── pending.js        # 会话级变更检查（本地工作区 vs 云端清单）
│   │   ├── repo.js           # 多仓库登记/绑定/repos.json（schema=2）
│   │   ├── registry.js       # DSH workspace.json 校验/修复/安全登记
│   │   └── git.js            # git/lfs 封装：身份、longpaths、commit/push、pull
│   └── host/                 # HTTP 适配层（只做参数校验 + 调 core + 组装响应）
│       ├── server.js         # http 服务、token、CORS、JSON、统一错误包装
│       ├── routes.js         # 全部 /api/* 处理器（见第 6 节）
│       └── views.js          # /api/tree、/api/cloud-view 聚合逻辑
└── client.js                 # 浏览器端入口（悬浮菜单 UI）。DSH 以脚本方式加载（__ModuleLoader__），保持单文件、无 ESM；内部按区域组织：API 封装 / 项目树 / 上传 / 下载 / 仓库管理 / 云端与同步 / 挂载
```

### 2.1 前端加载约束

DSH 以脚本方式加载客户端插件（`window.__ModuleLoader__.load({ id, factory })`），**不能使用 ESM import**。
因此前端保持单文件 `client.js`：文件内按"区域"划分函数（API 封装 → 项目树 → 上传 → 下载 → 仓库管理 → 云端与同步 → 挂载），
样式集中在顶部 `CSS` 常量。新增界面时在同一文件内加区域函数，不改加载方式。

前端只使用以下接口：`/api/health`（免鉴权探活）、`/token`、`/api/tree`、`/api/repos`、`/api/repos/remove`、
`/api/upload-project`、`/api/download-project`、`/api/pick-directory`、`/api/cloud-view`。

### 依赖方向（单向，禁止反向）

```
client  →  host/routes  →  core/*  →  shared.js
                 │              │
                 └──────────────┴─→ 文件系统 / git / lfs CLI
```

- `core` 不得 import `host` 或 `client`；
- `routes` 不得直接拼存储路径（通过 core 的 API）；不得写 git 命令（走 `core/git.js`）；
- `client` 只认 API 字段，不感知 store/index 布局。

## 3. 数据布局（云端仓库）

```
<repo>/
├── store/                                  # 存储区：只放内容
│   └── <项目名>/
│       ├── files/<原始相对路径...>          # 工作区文件内容（保持层级，可人工浏览/单文件下载）
│       └── large/<原始相对路径...>          # 大文件内容（git-lfs）
└── index/                                  # 指示区：清单、会话、映射
    └── projects/<项目名>/
        ├── meta.json                       # 项目元数据（cwd、aliases、sessions 等）
        ├── manifest.json                   # 路径 → {hash,size}
        ├── large.json                      # 大文件清单（路径/大小/哈希/存储状态）
        ├── conflicts/<时间戳>/<路径>        # 同路径不同内容时的隔离副本
        └── sessions/<会话id>/
            ├── session.v4.jsonl.zstd       # 会话日志（zstd 帧）
            ├── meta.json                   # 会话元数据
            └── workspace-ref.json          # 该会话对应的结构快照引用（不复制内容）
```

命名规则：`项目名 = <cwd目录名>__<路径键>`，路径键由 `layout.projectKeyOf` 生成（与 DSH 的 projectKey 算法一致）。

### 3.1 兼容 v1（只读）

| v2 位置 | v1 回退位置 |
|---|---|
| `index/projects/` | `projects/`（不存在 index 时） |
| 项目目录 `manifest.json` | `projects/<项目>/workspace/manifest.json` |
| `store/<项目>/files` | `projects/<项目>/(workspace/)files` |
| `store/<项目>/large` | `projects/<项目>/(workspace/)large` |

写入永远只写 v2 布局；v1 目录不会被自动迁移（M6 计划提供可选迁移脚本）。

## 4. 数据契约（schema）

所有 JSON 都带 `schema` 字段，读时容错、写时声明。

### 4.1 `meta.json`

```jsonc
{
  "schema": 1,
  "name": "test__D-deepseek-workspace-test",
  "cwd": "D:\\deepseek\\workspace\\test",
  "projectKey": "--D-deepseek-workspace-test--",
  "title": "test",
  "aliases": [{ "cwd": "D:\\...\\test\\sub", "scope": "sub" }],
  "sessions": ["session-..."],
  "workspace": { "files": 15, "changed": 0, "added": 15, "removed": 0 },
  "createdAt": "...", "updatedAt": "..."
}
```

### 4.2 `manifest.json`

```jsonc
{
  "schema": 1,
  "createdAt": "...",
  "files": { "notes/2025/a.md": { "hash": "<sha256>", "size": 123 } },
  "large": [{ "path": "data/big.bin", "size": 200000000, "hash": "...", "stored": "lfs|skipped|failed" }],
  "tooLong": [{ "path": "...", "size": 1 }]
}
```

### 4.3 会话 `meta.json` / `workspace-ref.json`

```jsonc
// sessions/<id>/meta.json
{ "schema": 1, "id": "session-...", "title": "...", "cwd": "...", "project": "test__...", "scope": "sub", "sessionFile": "session.v4.jsonl.zstd", "sessionBytes": 12345, "uploadedAt": "..." }

// sessions/<id>/workspace-ref.json
{ "schema": 1, "project": "test__...", "scope": "", "manifestHash": "<sha256 of manifest.json>", "files": 15, "capturedAt": "..." }
```

### 4.4 `repos.json`（本机 `%DSH_HOME%\cloud-sync\repos.json`）

```jsonc
{
  "schema": 2,
  "repos": [{ "id": "repo-xxxxxxxx", "name": "主仓库", "url": "...", "path": "...", "branch": "main", "addedAt": "..." }],
  "bindings": { "<项目名>": "repo-xxxxxxxx" }
}
```

约束：
- 同一 URL / 同一本地路径只能登记一次；
- 至少保留一个仓库；移除仓库时清理指向它的 bindings；
- **绝不自动登记仓库**（安装器与启动都只创建空登记表）。

## 5. 关键流程

### 5.1 上传（`POST /api/upload-project`）

```
校验 cwd/repo → ensureLfs + ensureGitConfig
        ▼
uploadWorkspace（core/merge.js）
  1. buildManifest(cwd)
  2. analyzeUpload：与目标仓库所有项目比较（cwd 祖先/后代关系 + 清单包含）
     ├─ 同 cwd            → mirror 更新（冲突隔离）
     ├─ 当前是子目录       → 写入父项目 <scope>/路径 + alias
     ├─ 当前包含旧项目     → 旧项目迁入新项目（文件加前缀、会话迁移、alias 重算），删除旧项目
     └─ 无包含关系         → 新项目 + 新 store 树
  3. 写入 store 内容 + index 清单 + workspace-ref
        ▼
uploadSession（勾选的会话，projectName/scope 由合并结果决定）
        ▼
commitAndPush（无变化不提交；推送失败只告警不破坏工作区）
```

### 5.2 下载（`POST /api/download-project`）

```
校验 repo/name/targetDir（必须是绝对路径）
        ▼
downloadWorkspace（core/download.js）：镜像 + 多余文件进 .csp-trash-<ts> + 逐文件哈希校验 + LFS 恢复
        ▼
downloadSession（可选）：cwd 改写为 targetDir → %DSH_HOME%\sessions\<projectKey(target)>\<id>\
        ▼
登记工作区：优先 ctx.workspaceRegistry.create(target,title)，否则 registry.registerWorkspace（写前校验/失败不写）
```

### 5.3 视图

- `GET /api/tree`：合并所有仓库的项目 + 本机会话，alias 归并到父项目行，供前端树视图；
- `GET /api/cloud-view`：按 工作区 → 会话 显示同步状态（clean/dirty/cloud-only/local-only），累计 pending 数；
- 安装目录内（`deepseek-harness\cloud-sync-tools`）未上传的工作区被忽略并计入 `ignoredInstall`。

### 5.4 启动自检（每次 DSH 启动）

1. `ensureRegistryFile()`：只创建空 `repos.json`，不登记任何仓库；
2. `registry` 校验/自愈由 `/api/registry-status`、`/api/registry-repair` 按需触发（不阻塞启动）；
3. 启动 HTTP 服务（仅 `127.0.0.1`），token 每次启动随机生成，`/token` 端点下发。

## 6. HTTP API（v2，前缀 `/api`，除 `/health`、`/token` 外都要 `?token=`）

| 方法 | 路径 | 请求要点 | 响应要点 |
|---|---|---|---|
| GET | `/token` | — | `{ ok, token, port }` |
| GET | `/api/health` | — | `{ ok, service, version, repoRoot }` |
| GET | `/api/repos` | — | `{ repos[], bindings, defaultRepoId }` |
| POST | `/api/repos` | `{url?/path?, name?}` | 登记（URL 唯一）；`{added, repos[]}` |
| POST | `/api/repos/remove` | `{id}` | 清理绑定后移除 |
| GET | `/api/tree` | — | `{suggestedBase, bindings, projects[]}` |
| GET | `/api/cloud-view` | — | `{repo, repos[], totals, projects[]}` |
| GET | `/api/sessions` | — | `{sessions[]}` |
| GET | `/api/projects` | — | 各仓库项目一览（含 repoId） |
| POST | `/api/upload-project` | `{repoId, cwd, sessionIds[]}` | `{output, projectName, scope, mergedInto?, migrated?, conflicts[]}` |
| POST | `/api/download-project` | `{repoId, name, targetDir, sessionIds[], withWorkspace}` | `{output, workspace, pendingLarge, sessions, registration}` |
| POST | `/api/pick-directory` | — | `{available, path?}`（无原生能力时 `available:false`） |
| GET | `/api/registry-status` | — | 校验结果 |
| POST | `/api/registry-repair` | — | 修复结果（含备份文件名） |

错误格式：`{ ok:false, error:"code", output:"中文说明", detail? }`；HTTP 400 业务错误 / 401 鉴权失败 / 500 内部错误。

v1 的 `/api/check`、`/api/upload`、`/api/download`、`/api/diff`、`/api/upload-sessions` **不保留**（客户端与宿主同版本升级）。

## 7. 不变量与安全约束（修改代码时必须保持）

1. **不自动登记仓库**：任何启动/安装路径都只创建空 `repos.json`；
2. **不破坏 DSH 注册表**：写 `workspace.json` 前备份、写后按 DSH 规则校验、失败不写入；
3. **不静默覆盖数据**：下载多余文件进回收目录；同路径不同内容进 `conflicts/`；
4. **工作区不上传安装目录内数据**：视图会忽略安装目录内的本地工作区；
5. **传输内容与清单一致**：`workspace-ref.manifestHash` 必须是 index 中 manifest.json 的 sha256；
6. **core 无 HTTP 概念**：便于单测与替换传输层；
7. **数据仓库必须 `* -text`**：上传前由 `ensureAttributes` 写入 `.gitattributes`（`* -text` + LFS），防止 git 行尾归一化改变文件字节、导致清单哈希在克隆后校验失败；历史数据可用 `tools/v2/repair-manifest.mjs` 修复；
8. **提交前不清理工作区**：git 失败只告警，不回滚用户文件。

## 10. 后续扩展点

- **新增 API**：在 `host/routes.js` 注册 `"METHOD /api/xxx"`，逻辑放 core，返回 JSON 对象；

- **数据演进**：schema 字段 + 读侧容错（见第 3.1/4 节），避免破坏旧仓库。

## 11. 术语表

| 术语 | 含义 |
|---|---|
| 项目（project） | 一个工作区在云端的实体：meta + manifest + sessions |
| 最大工作区 | 包含关系合并后的父项目；其 store 树覆盖子工作区内容 |
| alias | 被合并子目录工作区与父项目的映射（cwd → scope） |
| scope | 子工作区在父项目中的相对子路径（如 `sub`、`proj/sub`） |
| 存储区 store | 只存文件内容 |
| 指示区 index | 只存清单、会话与映射 |
| workspace-ref | 会话对应的结构快照引用（项目 + scope + manifest 哈希） |
